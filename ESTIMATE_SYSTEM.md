# Система отчетности подрядчика с ЛСР

## Обзор изменений

Система отчетности подрядчика переработана для работы с **Локальным Сметным Расчетом (ЛСР)**. Теперь подрядчик не указывает процент выполнения работ, а выбирает конкретные позиции из сметы и указывает фактически выполненный объем.

---

## Основные компоненты

### 1. Типы данных (`src/types/estimate.ts`)

#### `EstimateVersion`
Версия локального сметного расчета для работы.
```typescript
{
  id: number;
  work_id: number;
  version: string;              // "1.0", "2.0"
  created_at: string;
  created_by: number;
  created_by_name: string;
  is_active: boolean;           // Актуальная версия
  xlsx_file_url?: string;       // Ссылка на файл сметы
}
```

#### `EstimatePosition`
Позиция в смете (строка сметы).
```typescript
{
  id: number;
  version_id: number;
  name: string;                 // Наименование
  unit: string;                 // Единица измерения
  planned_quantity: number;     // Плановое количество
  base_unit_price?: number;     // Базисная цена
  current_unit_price?: number;  // Текущая цена
  position_number?: string;     // Номер позиции "1.1"
}
```

#### `WorkReportPosition`
Позиция в отчете подрядчика.
```typescript
{
  id: number;
  report_id: number;
  estimate_position_id?: number; // Связь со сметой (null для ручного ввода)
  name: string;
  unit: string;
  actual_quantity: number;       // Фактически выполнено
  is_manual: boolean;            // Ручной ввод (не из сметы)
}
```

#### `WorkReport`
Отчет подрядчика о выполненных работах.
```typescript
{
  id: number;
  work_id: number;
  version_id: number;            // Версия ЛСР на момент создания
  created_at: string;
  created_by: number;
  created_by_name: string;
  description: string;
  photo_urls?: string[];
  positions: WorkReportPosition[];
}
```

#### `EstimateComparison`
Данные для план-фактного анализа.
```typescript
{
  position_id: number;
  name: string;
  unit: string;
  planned_quantity: number;      // План
  actual_quantity: number;       // Факт (кумулятивный)
  percentage: number;            // Процент выполнения
  status: 'under' | 'normal' | 'over'; // Статус
}
```

## 2. Модальное окно отчета (`WorkReportModal`)

### Основные возможности:

1. **Добавление позиций из сметы:**
   - Dropdown с полным списком сметных позиций
   - Автоматическое заполнение наименования и единиц измерения
   - Указание только фактического количества

2. **Ручной ввод позиций:**
   - Checkbox "Добавить позицию вручную"
   - Заполнение наименования, единиц измерения и количества
   - Помечается бейджем "Ручной ввод"

3. **Описание и фото:**
   - Текстовое описание выполненных работ

## 3. Таб "Сравнение" (`EstimateComparisonTab`)

### План-фактный анализ материалов

Автоматически суммирует фактические объемы по всем отчетам и сравнивает с плановыми значениями из актуальной версии ЛСР.

#### Статистика:
- **Всего позиций** — общее количество позиций в смете
- **Выполнено** — позиции со 100%+ выполнением
- **В работе** — позиции с 1-99% выполнением
- **Не начато** — позиции с 0% выполнением

#### Карточки позиций:
```
┌────────────────────────────────────────┐
│ Радиаторы биметаллические 6 секций    │
│ План: 50 шт  •  Факт: 25.00 шт        │
│                                  [В работе] │
├────────────────────────────────────────┤
│ Процент выполнения         50%         │
│ ████████████░░░░░░░░░░░░░░             │
└────────────────────────────────────────┘
```

#### Статусы:
- **В работе** (< 90%) — синий
- **По плану** (90-110%) — зеленый
- **Перерасход** (> 110%) — красный с предупреждением

## 4. Кумулятивный учет факта

### Принцип работы:

Система **суммирует** все фактические объемы по каждой позиции из всех отчетов:

```
Отчет 1 (01.11): Радиаторы — 10 шт
Отчет 2 (05.11): Радиаторы — 15 шт
Отчет 3 (10.11): Радиаторы — 10 шт
────────────────────────────────────
ИТОГО ФАКТ:              35 шт
```

### Защита данных:
- ✅ Отчеты после создания **read-only**
- ✅ При повторном выборе позиции объемы **добавляются**, не сбрасываются
- ✅ Отчет привязан к **версии ЛСР** на момент создания

## 8. Версионность ЛСР

### Как работает:

1. **Загрузка новой версии:**
   - Пользователь загружает файл `.xlsx`
   - Система парсит и создает новую версию
   - Старая версия остается в истории

2. **Активная версия:**
   - Помечена флагом `is_active = true`
   - Только одна версия может быть активной
   - Используется для новых отчетов

3. **Привязка отчетов:**
   - Каждый отчет хранит `version_id`
   - При изменении сметы отчеты остаются привязаны к старой версии
   - Позиция удалена в новой смете? → помечается как "удалена в актуальной смете"

## 9. Интеграция с существующей системой

### Хранение данных:

**В текущей схеме БД:**
- `work_logs.materials` — временно используется для хранения JSON с позициями
- В будущем: отдельные таблицы `estimate_versions`, `estimate_positions`, `work_report_positions`

### Обратная совместимость:
- Старые отчеты с процентом выполнения — отображаются как раньше
- Новые отчеты с позициями — отображаются по-новому
- Проверка: `event.work_data?.positions` определяет новый формат
